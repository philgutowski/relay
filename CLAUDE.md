# Relay

Relay is a Claude Code plugin: an unattended outer loop that runs a list of independent tracker
tasks through the compound-engineering pipeline, one fresh headless `claude -p` process per task,
serially, and verifies each landing itself. `README.md` says why and how to use it. `CONCEPTS.md`
holds the vocabulary (Runner, Manifest, Lease, Task process, Closeout process, Halt class, Cause
line, Verify-landed); use those words.

## Layout

- `skills/relay/SKILL.md`: the `/relay` skill, which authors a manifest and launches the runner.
- `skills/relay/scripts/relay/`: the runner package. Python 3 standard library only, nothing to
  install. `relay_cli.py` beside it is the entry point (`validate`, `run`, `status`, `summary`,
  `verify`, `lease`).
- `skills/relay/templates/`: the briefs handed to the Task process and the Closeout process.
- `tests/`: the suite. Every test runs against the stub `claude` in `tests/stub-claude` with a
  temporary `HOME`; nothing launches a real model or touches a network. Fixture transcripts are
  generated by `tests/fixtures/transcripts/_make.py`.
- `docs/examples/`: one manifest per tracker adapter (jira, github, markdown).
- `docs/plans/`, `docs/brainstorms/`, `docs/ideation/`: the planning ladder, oldest decisions first.
- `docs/solutions/`: documented solutions to past problems, organized by category with YAML
  frontmatter (`module`, `tags`, `problem_type`). Relevant when implementing or debugging in the
  runner, the classifier, the closeout, the summary, or the adapters.

## Working here

- Run the suite from the repo root: `python3 -m unittest discover -s tests`. It takes about two
  and a half minutes; single modules run from `tests/` with `python3 -m unittest test_<name>`.
- Halt classes are a closed set in `contracts.py` (KTD6). A new outcome is a finding attached to
  a record, not a new class, unless the plan is amended.
- The runner never writes to a tracker. Every tracker write goes through a Claude process with
  the adapter's instructions; keep it that way.
- The stub cannot produce what a real process produces. After changing a contract between
  processes (the envelope grammar, the closeout terminal line, a brief template, the halt record,
  the classify digest keys), run one live task against a throwaway target before calling it done.
  `docs/solutions/logic-errors/stubbed-seams-agree-by-construction-first-live-run-found-five-contract-defects.md`
  is the reason.
- Prose in this repo uses no dashes of any kind. Commas, periods, or a new sentence.
